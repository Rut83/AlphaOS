# AlphaOS live-build reconstruction

This is a clean Debian live-build configuration derived from the uploaded AlphaOS ISO tree.

Observed source image structure:
- EFI/boot/bootx64.efi
- boot/grub/
- live/filesystem.squashfs
- live/vmlinuz-6.12.101+deb13-amd64
- live/initrd.img-6.12.101+deb13-amd64
- SHA-256 checksum files

The uploaded tree does not contain the contents of `filesystem.squashfs` or
`filesystem.packages`, so this configuration does not pretend to reproduce
unknown desktop packages or custom scripts. Add the actual AlphaOS package list
and custom files under `config/` as they are identified.

The installer is intentionally based on Calamares instead of hard-coded UUID
logic. Filesystem UUIDs should be generated by the installer when it formats
the target partition; Calamares then writes the installed system's fstab and
bootloader configuration.

## Build host

Use a Debian 13 (trixie) amd64 build host, preferably a VM or dedicated
machine. Install:

    sudo apt update
    sudo apt install live-build debootstrap squashfs-tools xorriso grub-pc-bin grub-efi-amd64-bin mtools dosfstools

## Build

    cd alphaos-live-build
    sudo ./auto/config
    sudo ./auto/clean
    sudo ./auto/config
    sudo ./auto/build

The resulting ISO should be `live-image-amd64.hybrid.iso` (the exact output
name can vary with the live-build version).

## Important

Do not copy the old `live/filesystem.squashfs` into this configuration unless
you intentionally want a frozen filesystem. Rebuild it from packages and
configuration instead.

The exact original desktop, package set, login manager, themes, and custom
installer scripts cannot be recovered from the supplied tree alone. The
uploaded tree only proves that the original image is a Debian-live style
image with GRUB EFI boot files and a SquashFS live root.


## Fix for recursive auto scripts

The `auto/config`, `auto/build`, and `auto/clean` wrappers use the `noauto`
argument when invoking live-build. This is required because live-build
automatically executes the corresponding `auto/*` wrapper; without `noauto`,
`auto/config` calls itself indefinitely.

## AlphaOS desktop branding

The live image now uses XFCE + LightDM, hostname `alpha`, live username `alpha`, AlphaOS release metadata, AlphaOS wallpaper/logo assets, Fastfetch, and Calamares branding. The live kernel command line explicitly sets `live-config.hostname=alpha` and `live-config.username=alpha`, which live-config supports for hostname and live-user creation.

## Debian 13 / Trixie package note

Do not add `policykit-1` to the package list. In Debian 13 (Trixie), the polkit runtime is split into `polkitd` and `pkexec`; Calamares' Debian settings package uses `pkexec`.
